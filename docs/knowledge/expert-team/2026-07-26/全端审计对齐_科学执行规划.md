## Phase I · 基础设施 (P0 · 必达)

### I-1 🐜 统一 Referral 体系

**问题**: 旧referral用Map内存存储，新referral-tracking用Prisma，两条体系不互通。

**操作**:
- 改造旧 referral.controller.ts → 注入 storefront ReferralTrackingService
- generateCode → referralTracking.createCode
- trackClick → referralTracking.trackScan
- trackSignup → referralTracking.trackConversion
- 删除旧 referral.service.ts 中的 Map 存储，保留路由兼容
- 旧 referral dto 保持不变（向后兼容），内部转发到新 service

**验证**: referral controller TSC 零错 + 旧路由仍可响应

### I-2 🐜 新建 storefront-management.controller.ts

**问题**: 所有17个storefront API都是@Public，管理端无法安全操作。

**操作**: 在 storefront 模块内新建管理端 controller:
```
apps/api/src/modules/storefront/
  └── storefront-management.controller.ts
```

**端点设计** (不@Public，需管理员权限):
- GET  bookings/list — 预约列表（分页/筛选/状态/门店）
- GET  bookings/stats — 预约统计（按日/周/月, 按门店）
- PUT  bookings/:id/status — 手动改预约状态
- GET  services/manage — 服务列表
- POST services/manage — 创建/更新服务
- GET  slots/manage — 时段列表
- POST slots/manage — 创建/更新时段模板
- GET  packages/manage — 套餐列表
- POST packages/manage — 创建/更新套餐
- GET  queue/list — 排队实时列表
- POST queue/call — 叫号
- POST queue/skip — 跳过
- GET  referral/overview — 推广总览（跨门店）

**权限**: @RequirePermissions('store:write')

### I-3 🦞 admin reservations 改接真实 API

**问题**: stores/[id]/reservations/page.tsx 使用8条硬编码mock数据

**操作**:
- 删除 mock DATA 数组
- 调用 reservation controller GET reservations (已有)
- 保留统计卡片/状态筛选/搜索/日历视图框架
- 接入 API 的 createReservation/updateStatus
- 按钮改为真实操作（确认→PATCH status=confirmed, 取消→DELETE）
