## 三、关键架构风险发现

### 3.1 两条 Referral 体系数据断裂 (🔴 P0)

```
旧体系: apps/api/src/modules/referral/
  ├── referral.controller.ts (generateCode/trackClick/trackSignup)
  ├── referral.service.ts (Map内存存储, 无Prisma持久化)
  └── referral.dto.ts

新体系: apps/api/src/modules/storefront/
  ├── referral-tracking.service.ts (createCode/trackScan/trackConversion/leaderboard/kolLink)
  ├── StorefrontReferralCode (Prisma model)
  └── StorefrontReferralRelation (Prisma model)
```

**问题**: 两条体系独立运行，数据不互通。旧体系用内存Map，重启即丢失。

**方案**: 废弃旧referral的Map存储，统一到新referral-tracking的Prisma模型。

### 3.2 管理端 API 基础设施缺失 (🔴 P0)

**现状**: storefront.controller.ts 17个端点全部 @Public()，面向C端。管理端操作（预约列表/统计/排队叫号/套餐CRUD）没有对应的管理API。

**方案**: 新建 `storefront-management.controller.ts`，非@Public，RequirePermissions('store:write')。

### 3.3 Admin reservations 全 Mock 数据 (🔴 P0)

admin-web stores/[id]/reservations/page.tsx 使用硬编码的8条mock数据，未接真实 reservation controller。

## 四、安全审计发现

### 4.1 @Public 端点防护不足

17个 @Public storefront API 虽有CSRF+RateLimit，但缺少：
- Referer/Origin 校验 ❌
- Device fingerprint ❌
- 预约接口无验证码 (批量刷预约风险) ❌

### 4.2 社媒安全就绪度

若上线模块C (社媒裂变13项)，当前安全防线覆盖仅 25% (2/8):
- 一键分享: 无防恶意刷 ❌
- 拼团: 无虚假账号防护 ❌
- 达人佣金: 无防刷单 ❌
- UGC: 无AI内容审核 ❌
- 直播带券: 无库存超卖防护 ❌
- 社群引流: 无二维码滥用防护 ❌

**裁决**: 社媒模块上线前必须完成安全加固清单（写入Phase 2合同）。
