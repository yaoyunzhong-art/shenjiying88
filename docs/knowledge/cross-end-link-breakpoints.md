# 跨端链路断点清单

## 1. 目的

本清单承接《TOB / TOC / 管理后台需求与现状对齐表》，用于把三端当前最关键的跨端链路断点显式列出，避免继续用“页面存在”替代“链路闭环”。

本文件当前只聚焦高价值主链：

1. 预约主链
2. 收银支付主链
3. 会员主链
4. 治理配置主链
5. 营销回流主链

## 2. 判定规则

1. `已通`：页面、API、权限、结果面基本能串起来。
2. `部分通`：链路主体存在，但中间仍有 mock / fallback / 口径分裂。
3. `断点`：至少有 1 个关键节点不存在、未接后端、或职责边界未冻结。
4. 断点优先级按业务损失和误判风险排序，不按页面数量排序。

## 4. 重点断点明细

### 4.1 预约主链

目标链：

- TOB 门户展示与品牌导流
- TOC 门店页 / 服务详情 / 在线预约
- API `storefront` 预约创建、改期、取消、核销
- Admin 门店执行与配置支撑

当前判断：

- TOC 预约真链路已经存在，是当前三端里最接近闭环的执行面。
- `appointments`、`booking` 等 TOC 页仍带 mock 痕迹，不能全部算入真实预约闭环。
- TOB 当前主要承担展示与导流，不是主预约执行面。
- Admin 还缺“预约配置 -> 门店执行 -> 履约反馈”的统一证明链。

断点结论：

- 预约链不是没有实现，而是缺少“三层职责穿透证明”。

### 4.2 收银支付主链

目标链：

- TOC 收银台 / 结算页 / 自助充值
- H5 支付与交易落单
- API cashier / transaction / member
- Admin 财务中心 / 退款 / 对账 / 规则
- TOB 财务经营视图

当前判断：

- TOC 收银、结算、充值是当前最强的消费者交易执行面。
- API 已具真实交易支撑。
- Admin 财务页和财务二级子域虽然结构齐，但仍混有 mock / fallback。
- TOB 财务看板更偏经营分析，不是控制面。

断点结论：

- 当前断点不在 TOC 执行面，而在“交易结果如何进入可信财务控制面”。

### 4.3 会员主链

目标链：

- TOC 登录 / 注册 / 会员中心 / 会员卡
- API 会员模型、权益模型、订单与券包
- Admin 会员管理 / 会员策略 / 会员运营
- TOB 客户经营 / SVIP / 品牌经营视图

当前判断：

- TOC 会员主链已经成型。
- TOB 和 Admin 均有会员运营面。
- API 同时存在 `member` 与 `membership` 两套入口 / 语义。

断点结论：

- 当前首要问题不是页面缺失，而是会员域正式口径未完全统一。

### 4.4 治理配置主链

目标链：

- Admin `foundation / configuration / approvals / openapi`
- API 权限治理、开放平台、审批与配置
- TOB `alerts / operations / governance / runtime`

当前判断：

- TOB 已具门户治理联动与展示能力。
- Admin 是主治理控制面，但部分页面仍偏 mock / demo。
- TOC 不承担治理主职责，只承接治理结果。

断点结论：

- 当前断点在“主控制面不够可信”，而不是“结果展示面不存在”。

### 4.5 营销回流主链

目标链：

- Admin 活动配置 / 券模板 / 规则引擎
- TOC 活动承接 / 核销 / 互动
- API 营销、会员、交易事件回流
- TOB 品牌活动、联盟经营、招商转化视图

当前判断：

- 三端都有营销域页面或功能入口。
- 但尚未形成统一的配置、承接、回流、经营复盘一张链。

断点结论：

- 营销域当前是“多点存在，穿透不足”。

## 5. 优先级顺序

### 5.1 P0

- `GAP-LINK-0001` 预约主链
- `GAP-LINK-0002` 收银支付主链
- `GAP-LINK-0003` 会员主链
- `GAP-LINK-0004` 治理配置主链

原因：

- 这四条链同时影响真实收入、真实履约、角色控制面可信度和最终复签结论。

### 5.2 P1

- `GAP-LINK-0005` 营销回流主链
- `GAP-LINK-0006` 报表财务口径链
- `GAP-LINK-0007` 工作台治理链

原因：

- 这些链路对经营判断和平台治理非常重要，但需要建立在 P0 主链先可信的前提上。

## 6. 下一步执行建议

1. 先把预约、支付、会员三条主链拆成逐节点穿透表。
2. 对 Admin 审批、财务、治理页标注 `real / fallback / mock`。
3. 对会员域补一张正式口径统一表，收敛 `member` / `membership`。
4. 对 TOB 和 Admin 的治理域补职责分层表，明确“主控制面”和“联动展示面”。
5. 对报表财务域补口径附录，禁止继续用页面值直接复签。
